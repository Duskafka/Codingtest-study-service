## 한 줄 요약

<!-- AI 초안: 자기 말로 다시 쓰기 -->
Spring Boot 3.5 대신 4.1을 골랐다. 3.5는 무료 보안 패치가 이미 끝났고, 언젠가 4로 가야 한다면 처음부터 4 방식으로 짜는 게 가장 비용이 적기 때문이다. 대신 3.x 기준 자료와 AI 코드를
4.x 방식으로 바꿔 써야 하는 수고를 감수했다.

## 배경

- 프로젝트를 시작하기 전에 Spring Boot 버전을 정해야 한다. 버전에 따라 의존성 버전을 맞추는 방식과 코드 작성 방식 (JSON 처리, 스타터 이름 등)이 달라진다.
- 사용할 스택: JPA/QueryDSL, Spring Security + JWT, springdoc, Redis, PostgreSQL (Supabase)
- 제약
    - 공개 서버 (AWS Lightsail 서울)에 배포하고, JWT 인증과 벌금 정산 (돈)을 다룬다. 보안 패치를 받을 수 있는지가 중요하다.
    - 이직용 포트폴리오다. 면접에서 버전을 고른 이유를 설명할 수 있어야 한다.
- 2026-11-17 기준 버전별 무료 (OSS) 지원 종료일

| 버전 | OSS 지원 종료       | 비고                                         |
|------|---------------------|----------------------------------------------|
| 3.5  | 2026-06-30 (종료됨) | 3.x의 마지막 버전. 마지막 무료 패치는 3.5.16 |
| 4.0  | 2026-12-31          | 약 6주 남음                                  |
| 4.1  | 2027-07-31          | 현재 최신 안정 버전                          |
| 4.2  | 2027-12-31          | 2026-11-19 출시 예정                         |

## 선택지

### Spring Boot 3.5

#### 장점

1. 강의, 블로그 등 대부분이 3.x 기준이라, 막혔을 때 자료나 Best Practice를 찾기 쉽다.
2. AI가 만들어 주는 코드, 그리고 회사들이 운영 중인 코드베이스와 환경이 가장 비슷하다.

#### 단점

1. 무료 지원이 이미 끝난 버전으로 새 프로젝트를 시작하게 된다. 2026-06-30에 Spring Framework 6.2와 Spring Security 6.5의 무료 지원도 함께 끝났다. 실제로 2026-08에
   유료 연장 지원 업체 (HeroDevs)가 Spring Security 6.5의 CVE 5건을 패치했지만, 무료 라인으로는 이 패치를 받을 수 없다.
2. 나중에 4로 옮기려면 마이그레이션이 필요하다. 한 커뮤니티 가이드는 3.5 → 4.0에서 바뀌는 지점을 115개로 정리했고, 그중 일부는 빌드는 통과한 뒤 런타임에서 깨진다.

### Spring Boot 4.1

#### 장점

1. 지원 기간이 남아 있고, 나중에 메이저 마이그레이션을 할 일이 없다.
2. HTTP Service Client, API 버저닝 같은 새 기능을 쓸 수 있다.

#### 단점

1. 자료가 상대적으로 적다. 블로그와 AI 코드가 3.x 스타일에 맞춰져 있어서 4.x 방식으로 바꿔 써야 한다.

- Jackson 패키지: `com.fasterxml.jackson` → `tools.jackson`
- 웹 스타터: `spring-boot-starter-web` → `spring-boot-starter-webmvc`
- Redis 직렬화기: `GenericJackson2JsonRedisSerializer` → `GenericJacksonJsonRedisSerializer`

2. 서드파티 라이브러리도 버전을 맞춰야 한다.

- springdoc은 Boot 4용 3.x 계열을 써야 한다. (Boot 3용 2.x 계열을 넣으면 기동 실패나 Swagger UI 404가 난다.)
- jjwt의 Jackson 모듈 (`jjwt-jackson`)은 Jackson 2에 의존한다. Boot 4에서 Jackson 2 지원은 deprecated라 다른 방법을 골라야 한다.

### 제외한 선택지

- 4.0: 무료 지원이 2026-12-31에 끝나서, 시작하자마자 업그레이드해야 한다.
- 4.2: 2026-11-19 출시 예정인 .0 버전이다. 첫 패치가 나온 뒤 4.1에서 올라가는 쪽을 택했다.

### 공통점

- 새 마이너 버전이 보통 6개월마다 (5월·11월) 나온다. 무료 지원만으로 운영하려면 1년에 1~2번은 마이너 업그레이드를 계획해야 한다.
- QueryDSL은 원조 프로젝트가 2024-01의 5.1.0 이후 릴리스가 멈춰 있다. Boot 4.1의 BOM도 5.1.0을 관리하므로, Boot 버전과 상관없이 안고 가는 리스크다.

## 결정

<!-- AI 초안: 자기 말로 다시 쓰기 -->

- 결정: Spring Boot 4.1.x로 시작하고, 4.2의 첫 패치 (4.2.1)가 나오면 4.2로 올린다.
- 결정을 가른 이유: 언젠가는 4로 가야 한다. 처음부터 4로 짜면 4.x 방식을 익히는 비용을 한 번만 낸다. 3.5로 시작하면 3 방식으로 짠 뒤 4 방식으로 다시 고치는 비용을 한 번 더 내야 하고, 코드가
  쌓일수록 그 비용은 커진다.
- 보조 이유
    - 공개 서버에서 인증과 돈을 다루는데, 3.5로는 무료 보안 패치를 받을 수 없다.
    - 사용할 라이브러리를 하나씩 확인한 결과 모두 4.x에서 쓸 수 있다. 조정이 필요한 건 JWT 라이브러리 하나다.
- 3.5를 선택하지 않은 이유
    - "많은 기업이 3.x로 운영 중"은 이미 돌아가는 서비스 얘기이고, 그 기업들도 지금 4로 옮기는 중이다.
    - "자료가 많다"는 실제 장점이지만, 의존성을 확인해 보니 호환 문제는 작아서 결정을 뒤집을 정도는 아니었다.

## 감수하는 것

<!-- AI 초안: 자기 말로 다시 쓰기 -->

1. 3.x 자료를 4.x로 바꿔 쓰는 수고

- 블로그, 강의, AI 코드를 그대로 붙이면 import나 스타터 이름이 맞지 않는다.
- 주의: `@JsonProperty` 같은 Jackson 어노테이션은 Jackson 3에서도 `com.fasterxml.jackson.annotation` 패키지 그대로다. 일괄 치환할 때 같이 바꾸면 안 된다.
- Redis의 새 직렬화기는 기본 타이핑 (default typing)이 꺼져 있어서, 예전 예제와 저장되는 JSON이 다를 수 있다.
- JPA 자료 상당수는 Hibernate 6 기준인데, Boot 4는 Hibernate 7을 쓴다.
- 실제 문제가 되는 조건: 4.x 기준 자료가 없어 공식 문서와 마이그레이션 가이드를 직접 읽어야 할 때 시간이 더 든다.

2. JWT 라이브러리를 하나 더 골라야 한다

- `jjwt-jackson` 대신 `jjwt-gson`을 쓰거나, Spring Security 내장 JWT 지원 (oauth2-resource-server)을 쓴다. → 추후 기능을 만들 때 결정

3. 마이너 업그레이드 부담

- 4.1은 2027-07-31에 무료 지원이 끝난다. 그 전에 4.2 이상으로 올려야 한다.

## 다시 본다면

<!-- AI 초안: 자기 말로 다시 쓰기 -->
이 결정을 다시 열 조건

- 꼭 필요한 라이브러리가 Boot 4를 지원하지 않고, 대체 수단도 없을 때
- 4.x 관련 문제로 개발이 계획보다 크게 밀릴 때 (예: 같은 원인으로 1주 이상 막힐 때)

정기 점검

- 4.2.1이 나오면 4.2로 업그레이드한다.
- 4.1 무료 지원 종료 (2027-07-31) 전까지 항상 지원 중인 버전을 유지한다.

### 배운 점

- 2026-11-17: 처음에는 "많은 기업이 3.x를 쓴다", "마이그레이션은 나중에 하면 된다", "4.x는 자료가 적고 의존성이 안 맞을 수 있다"는 이유로 3.x를 골랐다. 그런데 3.5의 무료 지원이 이미
  끝났다는 점을 빠뜨렸고, 사용할 라이브러리를 하나씩 확인해 보니 4.x에서 실제로 조정이 필요한 건 JWT 하나뿐이었다. 그래서 4.x로 바꿨다.
- 2026-11-20: <!-- AI 초안: 자기 말로 다시 쓰기 --> ADR-002에서 JWT 대신 Spring Session JDBC를 쓰고 Redis는 쓰지 않기로 했다. 그래서 '배경'의 스택 중 JWT·Redis와 '감수하는 것' 2번(JWT
  라이브러리), Redis 직렬화기 관련 내용은 이제 해당하지 않는다.
